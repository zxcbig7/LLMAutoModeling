六個工程核心

01
泛型引擎 EngineBase
<TModel,TVar,TExpr,TConstr> 四個型別參數把 solver 型別整個抽掉;新 solver 只實作 11 個合約方法。
02
物件即 Key
ModelElementBase.ToString() = ClassName@v1@v2。建立變數與約束引用同一物件、同一 key,零手工字串。
03
VariableBuilder
Expression 編譯建構子 + 笛卡爾積純字串產名,不建實例;熱路徑比反射版快 10 倍以上。
04
Source Generator
[OptVar] / [OptParam] 一行標記,AutoSetsGenerator 編譯期長出整個 class;attribute 注入使用端,零組件參考。
05
Pool API
LHS / RHS 雙池累積,送出時框架合併移項。人腦不做代數,限制式變成「照抄數學式」。
06
Experiment 遙測
Trial.Capture 快照設定 + 收斂數據;CSV 給人對照,JSON 給 LLM 學「設定 → 結果」。

Engineering Debt · Known Gaps
12 / 14
修好它們,前面的主張才算完整兌現

誠實的缺口清單

01
Generator 接線不全
框架 repo 內無任何專案以 Analyzer 參考 Generators,Templates 仍全 FORM 01;宣告式目前只在建模端透過 dlls 上線。
02
QTY 規則文檔不一致
docs 寫「已移除純 key 選項、QTY 強制」,code 仍留 HasValue=false。二選一收斂,別讓文件說謊。
03
ParseSet 型別字彙窄
宣告式只認 string / DateTime / int / double;runtime 已支援 long / decimal / enum,FORM 02 宣告不出來。
04
OptModel 綁死 CPLEX
組裝入口住在 Cplex 專案、Action<OptEngine> 吃 concrete 型別 —— solver-agnostic 在最後一哩破功。
05
軟約束 O(N²) 重建
每加一條 soft 就全量重建目標式(CPLEX 還先刪舊目標);應累積 penalty,solve 前一次套用。
06
解讀取逐筆 interop
GetSetVarValues 每個變數一次 native 呼叫;CPLEX 有批次 GetValues(INumVar[]),N 次可降為 1 次。

03 RULES
01
模型層零 solver 依賴

變數、參數、限制式、目標式不 import 任何 solver 型別;換引擎只換 OptEngine + Config。

02
宣告式 + 零建構子 = 樣板歸零

[OptVar] 一行長出 class;物件 ToString() 即變數 key,建立與引用永遠對得上。

03
每次求解都是可累積的實驗

Trial.Capture → CSV + JSON;人看得懂、LLM 學得會,自動調參的資料底座已經在跑。
