THE PIPELINE
05 / 18
THREE STAGES · 05

三階段，逐層收斂

PHASE 1
Modeling
自然語言 → 無歧義數學模型。保證「數學意義對」。
Sets · Params · Vars · Obj · Constraints
PHASE 2
Coding
模型機械式翻成可編譯可執行的 C#。保證「能跑」。
Parameter → Variable → Constraint → Program
PHASE 3
Tuning
先優化模型、再調 solver 旋鈕。保證「快且收斂」。
ExperimentRunner · CplexConfig
中間有一道「正確性 Gate」：解／目標值對得上問題描述，沒過不准進 Tuning。

PHASE 3 · TUNING
13 / 18
PHASE 3 · TUNING

先改模型，
再調旋鈕。

黃金順序：模型改一刀的效益，通常遠大於調十個 solver 旋鈕。tuning 只改求解策略，不改數學意義。
SOLVER KNOBS
14 / 18
SYMPTOM → ACTION · 14

Solver 旋鈕速查

TIMEOUT 但正確
提 timeLimit / mipEmphasis=1 / 開 parallelMode
GAP 過大
加切割 gomory/mir → nodeSelect=1 → 收 epGap
急找可行解
nodeSelect=0(DFS) → intSolLimit → mipEmphasis=1
記憶體爆
treeMemoryLimit + nodeFileInd=2/3（注意設定順序）
數值不穩
numericalEmphasis=true
要可重現
parallelMode=1 + 固定 randomSeed + detTimeLimit

GOLDEN ORDER
16 / 18
MODEL ≫ SOLVER · 16

優化的優先順序

1st 模型層
改數學結構
效益最大、最該先做。
  • 變數型態 CV ≪ IV < BV
  • 聚合 / 刪冗餘 / 收緊邊界
  • Big-M 取最小、對稱性消除
2nd Solver 層
調 CplexConfig
模型正確、只是慢時才動。
  • workThreads / 切割 / nodeSelect
  • mipEmphasis / epGap
  • null = 用 CPLEX 預設，只設要動的
TROUBLESHOOTING
17 / 18

最常見的四個坑

— 01
找不到變數
KeyNotFound：property 宣告順序與 Build*Vs 傳入 set 順序要一致。
— 02
Null 參考
LINQ 查 Parameter 回 null：用 ?.QTY ?? 0.0。
— 03
Infeasible
先查 LHS/RHS 移項錯；用 IIS 衝突分析定位。
— 04
順序錯
一定先 AddVariables、後 AddModel；目標/限制會用到變數。
