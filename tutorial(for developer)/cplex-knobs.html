CPLEX 22.1.1 的 .NET API 全部 182 顆參數都已是 OptimFoundation CplexConfig 的欄位。其中只有 109 顆能拿來做 tuning 實驗， 其餘 73 顆一律凍結。內容擷取自本機官方文件 %CPLEX_STUDIO_DIR2211%\doc\html\en-US\CPLEX\Parameters\topics\， 值與預設為 IBM 原文。點任一列展開官方值表。

五個分類回答同一個問題：這顆旋鈕能不能拿來做實驗。 名稱照「它在管什麼」取，看名字就知道該不該碰。

搜尋策略 109 · 可調

只有這一堆能拿來比。改 CPLEX 用什麼路線找答案，但答案的終點不變 —— 同一個目的地換一條路走。Emphasis、NodeSelect、各種 cut、 heuristic、前處理。

停止條件 27 · 凍結

管什麼時候算解完。MipGap = 0.03 和 0.01 是兩個不同的終點，拿它們比時間等於兩個跑者跑不同長度的賽道比秒數。

執行資源 9 · 凍結

管用多少機器、怎麼平行、怎麼計時。改了它量出來的時間本身就會變 —— 尺會伸縮。開跑前先定死。

重複量測 2 · 凍結

Seed 換一個是同一個設定再量一次，不是換了一種策略。 它贏只證明這個模型波動大。

非 tuning 35 · 凍結

輸出、顯示、讀檔上限、診斷、solution pool、CPLEX 內建 tune 的設定。 不改求解路線，掃它沒有意義。

實測驗證與已知地雷

  1. 538 個官方合法值逐一實跑過。 SolverParamValueMatrixTests 對 182 顆旋鈕套用 IBM 文件列出的每一個合法值， 各建一次 MILP 真求解。538 個裡有 7 個被 CPLEX 拒絕，其餘全部可用。
  2. 兩顆會炸掉整輪的旋鈕，別掃。 BendersStrategy = 1/2/3 在沒有 Benders 註記的模型上丟 Error 2000: No Benders decomposition available； OptimalityTarget = 2 在 MIP 上丟 Error 1017: Not available for mixed-integer problems。 這兩個是丟例外，不是靜默無效 —— 進 variant 池會讓整輪實驗中斷。 純 MILP 上安全值：BendersStrategy 只有 -1 和 0， OptimalityTarget 是 0 1 3。
  3. CpuMask 在本機平台完全不能用。 設任何值都丟 Error 1811: Attempt to invoke unsupported operation， 連官方文件列的預設值 "auto" 都設不進去。CPLEX 自己的 Interactive Optimizer 執行 set cpumask auto 同樣被拒 —— 是平台不支援，不是框架的問題。
  4. 官方文件與實際值域對不上的地方。 Seed 上限是 2100000000（文件只寫「any integer」，超過丟 Error 1015）； PopulateLimit 與 TuningRepeat 文件寫「any nonnegative integer」， 實際最小值是 1，設 0 會被拒。另有 8 顆的最小值是 1 而非 0。
  5. Threads 的預設是框架的，不是 CPLEX 的。 CPLEX 官方預設 0 = automatic，但 CplexConfig.Threads 有 property initializer = 32。不明設就等於在每台機器上硬餵 32。 六個欄位有非 null 初始值，只有這顆真的偏離官方預設。
  6. 掃描順序不是照這張表。 109 顆是「合法可動的上限」。每輪仍要先從收斂軌跡判剖面，只掃對應那一類，一輪一顆 —— 見 solver-tuning-guide.md §2.1 / §2.2。
